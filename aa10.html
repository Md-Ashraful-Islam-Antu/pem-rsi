Two types of scheduling

Resource management determines how labor and equipment are assigned to project activities. The two primary problems are resource leveling (minimize peak while keeping deadline) and resource allocation (extend deadline to meet resource constraints).

Exam focus: Given a network with resource requirements per activity, draw the manpower histogram, perform leveling (move non-critical activities to reduce peak), and report the new histogram. Numerical is worth 15–17 marks.

Key rule for leveling: Only move activities that have slack (non-critical activities). Never move a critical activity — that would extend the project deadline.

The 4M Resources (Sakib Notes)

Sakib Notes introduces the 4M framework for thinking about ALL project resources. Resource management applies to all four Ms simultaneously.
MResourceWhat It CoversLeveling Applies?
M1 Man (Labor) Human resources — project team members, workers, contractors, consultants. Skills, availability, working hours. ✅ Primary focus of resource leveling — manpower smoothing
M2 Machine (Equipment) Machinery, tools, facilities, vehicles, computers, lab equipment used by the project. ✅ Equipment utilization can be leveled (avoid peaks of equipment sharing)
M3 Material Raw materials, components, supplies, inventory consumed or used by the project activities. ⚠️ Partially — procurement scheduling can be smoothed
M4 Money (Budget) Financial resources — budget, cash flow, funding available at each stage of the project. ⚠️ Time-phased budget = financial resource leveling concept
Important: Resource leveling requires homogeneity of manpower — the assumption that all workers of the same type/skill are interchangeable. This simplification allows the mathematical smoothing procedure to work. In reality, skill differences make exact leveling harder.
🧮 Heuristic Approach — Priority Rules ★★★★
When resources are limited and you can't optimize perfectly, heuristic rules (rules of thumb) determine which activity to schedule first. These are for resource-constrained scheduling.
RuleFull NamePriority Given ToWhen Useful
ASAP As Soon As Possible Schedule each activity at its earliest start Maximize early completion; default starting point
ALAP As Late As Possible Schedule each activity at its latest start Delay resource use; maintain maximum flexibility
STF Shortest Task First Shortest duration activity gets resources first Maximize number of activities completed early
MRF Minimum Resources First Activity needing fewest resources goes first Preserve resources for larger tasks
MSF Minimum Slack First Activity with least slack (closest to critical) goes first Protect critical/near-critical activities; most common
Arbitrary Random / First-come No formal priority; first in list goes first When other rules don't apply or for benchmarking
MSF (Minimum Slack First) is the most commonly recommended heuristic because it protects the critical path — activities closest to critical should get resources before activities with lots of float.

❓ Past Year Questions & Full Answers — AA Ch 10
Resource leveling (★★★★★) is the highest-marks question here. Know how to draw both histograms and explain the leveling decisions.

Q1. Resource leveling — Procedure with example. [15–17 marks, ★★★★★]

Concept: Resource leveling smooths out resource usage peaks by delaying non-critical activities within their available slack. The project deadline is NOT changed.

Procedure:
Step 1: Perform CPM analysis — identify critical path, ES, EF, LS, LF, and slack for all activities.
Step 2: Draw the ASAP (As Soon As Possible) resource histogram — bar chart of resource demand vs time.
Step 3: Identify peaks — periods where demand exceeds the desired limit.
Step 4: Move non-critical activities (those with slack) to later times within their slack window to reduce peaks and fill valleys.
Step 5: Draw the new leveled histogram and verify that: (a) the project deadline is unchanged, (b) all activity precedences are respected, (c) no activity exceeds its Latest Finish time.

Key rule: Critical path activities CANNOT be moved. Only non-critical activities can be delayed.

[In the exam: draw the original histogram using ASAP schedule → identify which non-critical activity to move → draw the leveled histogram. Label resource units on y-axis and time periods on x-axis. Show before and after clearly.]

Q3. Explain 5 priority rules for constrained resource scheduling. [5–8 marks, ★★★★]

Answer:
When resources are limited and multiple activities compete, these rules decide which activity gets the resource first:

1. ASAP (As Soon As Possible): Schedule each activity as early as its predecessors allow. Builds in maximum float — does not consider resource limits.

2. ALAP (As Late As Possible): Delay each activity to its Latest Start. Frees resources early but risky — no float left for critical activities.

3. LST (Least Slack Time / Minimum Slack First — MSF): Give priority to the activity with the least slack (closest to critical). Prevents critical activities from being starved of resources. Most widely used rule.

4. SDF (Shortest Duration First): Do the quickest job first. Frees resources rapidly, but may delay long-duration critical activities.

5. LDF (Longest Duration First): Schedule long jobs first to prevent them from being pushed to the end. Useful when long activities are hard to interrupt.

MSF (Minimum Slack First) is generally preferred because it prevents critical path delay by prioritizing near-critical activities.

Q4. What is the MSF rule? Why is it preferred? [3–5 marks, ★★★]

Answer:
The Minimum Slack First (MSF) rule — also called Least Slack Time (LST) — assigns resources first to the activity with the smallest amount of remaining slack (LS − ES).

Why it is preferred:
1. It directly prevents project delays — activities closest to the critical path (least slack) get resources first
2. It is intuitive — the most "at-risk" activity from a schedule perspective gets priority
3. It naturally protects the critical path even as the schedule evolves
4. Empirical studies show it produces better (shorter) project durations than most other rules under resource constraints

Compare: SDF (Shortest Duration First) is fast to implement but can starve long-duration critical activities. MSF is smarter because it uses schedule information, not just activity size.
